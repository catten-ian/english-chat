# Bellweather: The Quiet Tide — 重做设定与开发规格 v2

日期：2026-11-11。状态：供评审的设计提案，本文新增剧情、系统、指标均为待实现规格。

当前 beta 是技术原型，不满足开放探索、双版本美术、角色知识隔离和持久化反馈等完整要求。本轮只编写此设计，不修改代码、服务或部署。后续全部开发限定在 `feat/world-game`，沿用独立 beta 发布路径。

## 1. 当前实现的问题与处理结论

下列事实来自本地代码核查；本轮没有重新执行公网 GUI 验收。

| 问题 | 核查位置 | 影响及处理 |
|---|---|---|
| 目标截图直接作为 2D 背景，移动只改变背景位置 | `css/world-game.css` 的 `.world-scene`；`js/world-game.js` 键盘处理 | 不是可探索 2D 世界；截图还自带人物与 UI。必须换成独立场景、角色、交互层。 |
| 3D 为方块建筑、胶囊身体、球体头部 | `initThree()` | 仅能作内部灰盒；不能作为最终人物与环境美术。 |
| 无真实 NPC 距离、视线、碰撞和地点交互闭环 | `renderPeople()`、`world-talk`、键盘处理 | 选择名字即可跨场景聊天；探索与调查脱节。重做空间与交互系统。 |
| 同章关键答案直接注入每个 NPC 的 `stage.facts` | `scopedNpc()`、`WORLD.stages` | 即使没有传 `judgeOnly` 字段，也已泄露等价内容。需要内容级知识审计。 |
| 角色只有简短语气和少量事实 | `WORLD.npcs` | 无个人目标、关系、误记与可持续对话状态。重写角色书。 |

| 用户消息含关键词就可能解锁线索 | `submitSpeech()` | 猜词、否定句和套话都可获得伪线索。改为有来源的引擎事件。 |
| 答对至少一题即可通过，失败界面也调用 `nextStage()` | `settle()`、`nextStage()` | 可绕过调查和章节门槛。改为服务端可验证条件。 |
| 有答题处理函数，但当前 HTML 未配置对应可见的 `world-quiz` 入口 | `index.html`、`handleAction()` | 功能不形成玩家可达闭环。每个动作必须有可发现入口。 |

| 游戏状态使用固定 localStorage 键 | `STORE` | 不按账户/旅程隔离，没有跨设备权威存档。迁移到服务端。 |
| 自定义提供商探针只检查有无回复 | `maybeProbeCustomProvider()` | 不能验证角色隔离、结构化输出或流式能力。重做能力与隔离测试。 |
| 3D 循环覆盖人物 X 坐标；2D→3D 再切回的动画循环生命周期不完整 | `animate()`、`toggleView()` | 输入和视觉状态可能不一致；离开游戏也缺少完整资源回收。拆模拟、渲染生命周期。 |
| 没有目标图/实时截图独立评审和帧率达标证据 | 现有交付记录 | 不能声称 Dream Loop 完成或画面达到目标。补完整 Pro 验收。 |

可保留并审计：现有登录/提供商选择接口、SSE 基础传输、英文文本输入、折叠反馈入口、服务端不直接返回答案字段的思路。世界内容、推进状态、线索判定和图形主体都需要重做。

## 2. 产品定义与设计来源

一句话：玩家作为新到任的港务见习调查员，在一座漂亮、可自由走访的海湾小镇里，用英语建立关系、核对证词、调查失去联络的渡船，并决定如何公开真相。

核心体验：好奇 → 观察 → 询问 → 发现矛盾 → 核实 → 作出有证据的判断 → 看到人物和环境改变。

英语是完成交流的工具。NPC 根据表达的实际意思交流；语法不完美不阻止任务。学习报告在后台积累，由玩家选择何时查看。

设计借鉴是机制参考，不复制其世界、文本或美术，也不声称本轮完成过外部资料检索：

- 《Outer Wilds》：同一空间在获得新知识后产生新的意义；不复制循环时间惩罚。
- 《Return of the Obra Dinn》：将证词、时间、位置和实物交叉核验；把知道与猜测分开。
- 《Disco Elysium》：每个人有工作、处境、立场与不愿面对的问题；不把角色写成问答终端。
- 《A Short Hike》：紧凑开放地图、友善探索、少量值得绕路的支线。
- 阿加莎·克里斯蒂式公平推理：读者/玩家能在揭晓前接触必要证据；误导有事实来历。
- Tavern 角色书/世界书：可重用的世界条目、角色关系、语气、事件记忆；授权逻辑由引擎实现，不靠关键词检索决定能否读秘密。

首季范围目标：5 个阶段、8 位主要 NPC、7 个区域、约 3–5 小时首次游玩。每阶段目标 25–45 分钟，可随时保存退出。时长、内容量与性能均为设计目标，需实际游玩校准。

## 3. 世界与玩家

游戏名为《Bellweather: The Quiet Tide》，中文暂名《钟湾：静潮》。小镇统一命名 Bellweather；旧原型的 Greyhaven 不再混用。

时代：架空近现代沿海小镇，有电灯、无线电、纸质调度单和小型工作船。服饰、建筑与道具统一为有年代感的海港生活风格。

玩家：Alex，成年港务见习调查员，可选预制外观与称呼，背景固定为刚到镇上、认识基本港口术语但不了解当地人情。玩家没有预知真相的私人设定，也没有让所有居民自动信任的身份特权。

开场：黄昏暴风雨刚过，旧码头的一盏引航灯消失，工作渡船 Wren 没有按时回港，无线电最后一句报告被雨声吞掉。镇上有人说听到求救钟，也有人坚持只是松脱的铁门。玩家先受托找到灯和渡船，调查逐渐指向一份写着“已送达”的通知。

主题：人们不一定在说谎，也可能只看见了一小部分；负责的决定需要核实；体谅一个人的处境不等于替他隐瞒事实。

基调：温暖、清冷、有人情的悬疑。无强制战斗、跳吓、死亡读档；风暴有叙事压力，但查词、组织英语和看反馈期间没有真实时间倒计时。

## 4. 地图与空间玩法

首季约 350×250 米可游玩范围，通过弯曲街巷、高差和视线遮挡形成真实尺度感；后续按场景测试调整，不为面积增加空路。

| 地区 | 美术与声景 | 玩法与阶段变化 |
|---|---|---|
| 港口广场/港务室 | 暖窗、石板路、雨后告示栏、钟声 | 接任务、看调度记录、提交调查结论；最后张贴新规。 |
| 湿木码头/船匠棚 | 绳索、渔网、木板反光、系泊船 | 检查空灯座、修理记录、相互矛盾的证词。 |
| 灯塔山径/值守室 | 海雾、灌木、远景灯塔、风声 | 观察海湾、访问 Eli；完成后出现稳定引航灯光。 |
| 市场街/茶馆 | 橱窗、茶汽、雨棚、生活声音 | 居民日常、误认来源、可选关系支线。 |
| 修理工坊 | 木屑、灯具、工作台局部暖光 | 找到缺失灯具、比较工单；后期开启维修交互。 |
| 东侧施工口/潮汐步道 | 岩石、水线、路障、金属门 | 检验证词与钟声；阶段事件改变可走路径。 |
| 废采石湾/避风棚 | 狭窄入湾、旧吊机、蓝色船篷 | 找到 Wren、见到新 NPC、取得船上文件。 |

区域关系：广场连接码头、市场街和灯塔山径；码头连接工坊与东侧施工口；东侧步道在剧情确认安全后通往采石湾。回程可用已建立的便捷通路，减少无意义重复走路。

开局自由走访镇内主要公共区域。工坊里屋、船舱和危险步道需要合理的角色许可或安全事件；锁门必须提供可理解的世界内原因，不以“英语等级不足”挡路。

NPC 有位置和短距离活动轨迹；角色外出会留去向线索。普通对话必须由玩家实际走到 NPC 的交互半径内触发，且服务端同时校验玩家位置、NPC 位置、当前地点、视线/遮挡和 NPC 是否在场。菜单只列附近且当前可见的角色，不能跨地图瞬间切换所有角色。无线电只作为后续明确设计的剧情交互，第一章不提供自由拨号例外；任何远程通讯都必须有已解锁的世界内设备、范围和任务条件，并由服务端单独授权。

| Ada Finch，46，邮务/调度员 | 整齐衬衣、旧眼镜、纸张墨迹；语速稳 | 想把流程补救好；不愿替任何人篡改记录 | 投递批次、路线单缺页、自己未取得签收；可指出两个版本的纸张编号 | 不知道海上发生什么；没有看见灯的拆卸过程。 |
| Martin Voss，52，港务长 | 保养得体的旧制服；讲程序、在压力下防御性强 | 保住港口与自己的职位；担心承认失误引发停运 | 签过有前置条件的工单；未收到替代标记确认；自己提前在表上记了“通知送达” | 不知道船是否受损及真实避风处；不能让他在任何章节知道整场所有见闻。 |

所有成年人均使用正式角色资产和统一美术规格。角色吸引力来自面部、发型、服装、姿态、材质和性格表现，不能用复制同一人模换颜色代替。

关系值只描述具体关系事实，例如“愿意让你进工坊”“愿意补充上次没说完的经历”。不显示可通过夸赞刷满的泛用好感条。必要证据有替代路径，失礼对话不会永久锁死主线。

## 7. 五阶段主线

| 阶段 | 玩家公开目标 | 必要调查组合 | 核心认知变化 | 提交与可见变化 |
|---|---|---|---|---|
| 01 The Missing Lantern / 消失的灯 | 找到旧码头灯，解释灯为何不在原处 | 空灯座、Mara 证词/工单、工坊灯具；Eli 用于排除灯塔故障 | 灯被按单拆下，现场替代标记却未完成；不是凭外观认定盗窃 | 向港务室提交初步判断；工坊合作开放，旧口出现明确禁入标记。 |
| 02 Three Bells, One Echo / 三声钟，一声余响 | 判断钟声说明什么，是否有足够依据宣告遇险 | Eli 含糊记忆、Rowan 的铁门经历、工作钟声卡、照片时间 | 不同来源被混成了同一声序列；只支持“可能已泊”，仍需找船 | 选择下一步核查行动；开放潮汐步道调查，不直接宣布救援完成。 |
| 03 Where the Wren Waits / 渡船停在哪里 | 核实渡船所在，选择到达路线 | 施工图、潮位步道标记、观察点可见船篷/桅杆、旧路线单 | 渡船在采石湾避风；本地旧路径和现行施工信息有矛盾 | 安全到达并与 Jonah 交谈；三人状态由亲见确认；获得船上版本文件。 |
| 04 Marked Delivered / 已送达 | 查明为什么暂停通知没到船上 | 船上旧单、Ada 投递记录、无签收凭据、Voss 经历 | 个人猜测转为可证明的流程失误；提前勾选送达是责任核心 | 事实报告解锁；Voss 可回应具体证据，不能靠一句认罪生成真相。 |
| 05 First Light / 第一束光 | 提交完整报告，完成复航前核对 | 已验证时间线、维修验收、船员确认、书面交接 | 理解事故链，区分确定事实、证词和无法证明的指控 | 通过步骤核对完成虚构维修交互；灯光恢复、渡船回港、人物回应报告。 |

每阶段提供 2–4 个核心判断和少量可选问题，具体数量随可用证据确定。题目在世界内表现为无线电回复、调查札记或港务报告选项，而不是随时弹出的一套无关考试。

阶段切换推进故事时段：黄昏 → 蓝调时刻 → 深夜 → 黎明前 → 日出。玩家需要明确选择“继续任务”；查词、组织语言和查看历史不消耗剧情时间。

提交失败回当前阶段，保留已获得证据。提示下一处可调查来源，不直接揭示答案。没有“一题答对即通关”；关键结论须正确、已获取规定证据、完成必要操作，且由服务端授权转换。

结局以同一事实基础上的处理方式分支：完整公开并推动修复、证据不完整的草率指控、或只解决眼前问题。主线允许玩家返回补调查；英语语法不决定好坏结局。

可选支线：帮 Nia 写一条区分事实与猜测的照片说明；替 Rowan 与姐姐完成一次解释；记录 Eli 的灯塔口述史。支线训练转述、道歉和澄清，奖励关系片段、美景机位或角色日记，不提供完成主线必需的唯一线索。

## 8. 第一阶段可直接实现的玩法脚本

### 8.1 开场与第一次成功

玩家在湿木码头落地。镜头前有空灯座、远景灯塔、Mara 的工坊暖窗和 Eli。屏幕边角仅显示“Find the missing lantern”。进入交互距离显示 E/点击交谈，输入栏在对话开启后出现。

玩家调查空灯座，获得 E01：螺栓被整齐拆卸；这支持“可能有工具参与”，单独不能证明授权拆卸。线索日志显示玩家真正看到的内容及地点，不写幕后真相。

玩家问 Eli：`Did the lighthouse stop working too?` Eli 可回答透镜检查结果和他看见的东侧灯熄灭；不能回答拆灯工单、Mara 的行动原因或渡船位置。

玩家到工坊问 Mara：`Where is the old lantern?` 她知道自己拆过灯，可以自然说明位置。她不需要等玩家命中指定关键词，也不靠任意好感数值藏这条常识。

### 8.2 证据链

| ID | 获得方式 | 实际内容 | 能支持的结论 | 不能证明的结论 |
|---|---|---|---|---|
| E01 | 调查空灯座 | 螺栓整齐拆卸，没有明显撞坏痕迹 | 值得查工具和维护记录 | 谁拆的、是否获准。 |
| E02 | 与 Mara 对话，获得明确可追溯陈述 | Mara 说自己按工单拆灯，灯在工坊 | 她承认行为并提供可核验去向 | 工单一定真实、通知一定送到。 |
| E03 | 经允许查看工坊灯具 | 铭牌编号匹配，灯具完整 | 缺失灯具已找到 | 船员知道灯被移走。 |
| E04 | 检查签署工单 | 拆卸获准；复航有替代标记/通知条件 | 拆卸有授权，交接条件存在 | 条件已经落实。 |
| E05 | 查看旧口与替代支架 | 替代标记尚未就位 | 当下不能按完成维护处理 | 谁应承担全部责任。 |

主线判定使用 E03 + E04 + E05；E01/E02 提供探索指向和交叉核验。以后可增加等价证据路径，但不能删成“说出灯在工坊即可通关”。

### 8.3 多轮口语交流示例

```text
Player: The light gone because storm?
Eli: You mean the light at the old pier? The lighthouse lens is fine.
     I saw the pier go dark before I came down here.
Player: Yes, that one. Did you see anyone take it away?
Eli: No. Mara was working near the workshop earlier. You could ask her.
Player: Thanks. I'll check with her.
```

Eli 知道“见过 Mara 在工坊附近”必须事先写入他的亲历书；没有这条事实就不能生成这个指路句。此示例是一项内容编写要求，不授权模型随意补全。

后台学习笔记：原句容易理解；更自然的说法是 `Did the light go out because of the storm?`；一般过去时提问可用 `Did ...?`。不把省略句一律判为严重错误，不打断角色回答。

### 8.4 结论与后果

问题示例：`What can you confirm about the missing lantern?`

A. A storm destroyed the lighthouse lens.
B. Someone stole it to stop the ferry.
C. It was removed for scheduled work, but the replacement marker is not ready.
D. The ferry crew removed it after leaving port.

必要证据：E03、E04、E05。内部答案为 C。选项顺序按旅程固定随机，不让正确答案始终位于同一位置。答案键仅在服务端。

若选 B，角色不会立刻同意存在盗窃；日志指出“目前物证能确认灯的去向，尚不支持动机”，并允许回去核查。正确提交后，玩家看到旧口被标记暂停使用、Mara 允许查看后续维修材料，第二阶段调查入口自然出现。

## 9. 对话、线索与 AI 的职责

自由文本是主要交流方式，建议问法用于提供语言支架，可编辑、可隐藏。初次见面、追问细节、请求澄清、转述他人说法、展示证据、总结推理都应可用。

AI 负责自然措辞、人格表达、已授权事实的解释和有限意图识别。引擎负责真相、证据归属、角色实际知识、解锁条件、物品、位置、任务状态和存档。

自由聊天分成两条逻辑路径：

1. 服务器按人物/阶段/地点整理有权限的事实与历史，生成可流式展示的自然回复。
2. 交互层根据规则与经校验的结构化结果提交事件，事件必须引用该 NPC 拥有的事实 ID、已完成动作和当前 turn ID；不把自然语言回复直接当数据库命令。

没有“用户说 saltwater，所以给他盐水线索”的正则规则。玩家提出猜想可写入自己的假设笔记，但状态为未核实，不能变成已取得证据或 NPC 的个人记忆。

NPC 接到玩家转述时，只能知道“玩家声称 X”，不能把 X 升格为自己亲见的事实。选择展示一件证据需要服务端验证玩家拥有该证据；不是自动把玩家证据书挂到 NPC 上。

流式回复显示进行中和可取消状态；错误必须以连接状态呈现，不能伪装成角色真的说了某句回避台词。重试复用 turn ID，避免重复消耗、重复发放线索。断流保留未完成文本标记，结构化事件完整校验前不推进任务。

## 10. 世界书分卷与模型权限

| 分卷 | 挂载/生命周期 | 可读对象 | 约束 |
|---|---|---|---|
| global | 世界常驻 | 玩家、所有 NPC；生成/结算服务按任务取用 | 仅公共地理、制度、当前公开事件。不能暗藏作者真相。 |
| stage_01…05 | 当前阶段进入加载、退出卸载 | 玩家、本阶段 NPC、判题器 | 仅同一范围内确实公共的事实。目击经历仍归角色私有书。 |
| char_* | 绑定 owner | 仅该 NPC | 亲历、听说的来源、信念、模糊记忆、目标、关系和知识空白。 |
| evidence / player_evidence | 玩家 persona/线索日志 | 仅玩家 | 记录来源与可靠性，不自动注入角色、出题或判题模型。 |
| judge_only | 仅最终或阶段结算时按阶段范围加载 | 仅结算判题器 | 真相、可揭晓范围和作者核验说明；不提前加载未来章节。 |
| feedback | 后台独立 worker | 仅英语反馈/汇总服务与玩家报告页 | 不进入角色、问题生成或叙事判题上下文。 |
| runtime | 引擎 | 不注入任何模型 | 实体、权限、判定规则、事件状态、物品和答案键。 |

每个 NPC 的世界书读取集合必须是 `global + current_stage_public + char_entries(owner == npcId)`。另带该 NPC 的服务器可信会话历史，其他人的私聊不会被塞入历史摘要。

共享 stage 不是“本章作者知道的一切”。例如第一章公共书只写“旧码头灯消失、Wren 尚未回港、工坊对外开放”，不会写“Voss 提前勾了送达”。字段名安全不代表内容安全，编译时审计同义表述和隐含推论。

模糊记忆示例：`Eli 记得远处有几声金属响。风向变过，他左耳听不清，后来回想有时是三下，有时像多了一下。` 不把精确声数或来源放进他的书，再要求他假装不知道。

误认示例：`Nia 没看清背影的脸，凭黄雨衣认作 Eli。` 不写她知道那是 Mara。

回避示例：`Rowan 去过禁入区；他担心自己因此失去学徒工作。` 允许他紧张与回避来自处境；他不知道的船位不随回避理由一起注入。

中性空白：`Ada 没有见到渡船离港后的航行。` 不写“她不知道船在采石湾”。

新增事实条目需要 ID、owner/visibility、来源、发生时段、确定性、适用阶段和知识生效事件。编译器拒绝缺失权限、跨 owner、未授权未来事件与重复冲突事实。

问题生成模型只接收明确允许用于该问题的公开信息与玩家已获得证据的最小摘录。摘录是有来源的受控输入，不是挂载整本 player_evidence。结算模型同样只读必要证据摘录和自己的 judge_only 切片。

提示注入不能获得模型从未读到的私有书；但模型仍可能猜出事实、顺从玩家或编造，所以不能承诺“绝对不说对答案”。必须同时限制秘密分发和模型输出能产生的引擎权限。

自定义提供商接收的上下文可被该提供商看到；该事实应在配置说明中清楚呈现。不同 NPC 请求已授权地发送到同一不可信提供商时，应用不能保证该提供商不跨请求关联内容。随机探针也不能证明其完全可信。

## 11. 题目生成、判题与后续交互拓展

每个判断先由作者定义可验证的“问题蓝图”：考察结论、必要证据 ID、允许误导、选项数量、正确语义约束、何时可提交。AI 只在这些边界内生成措辞与干扰项；不能自由发明事故原因、添加不存在的线索。

出题器不会读 judge_only。它从玩家已掌握证据生成可回答问题；引擎的确定性规则负责验证正确选项与证据充分性。生成失败或选项歧义时重试一次后使用审核过的作者题，并在诊断中记录回退，不能冒称本题由 AI 成功生成。

答案与证据归属保存在服务端，题目绑定 `user_id + run_id + stage_id + content_version`。客户端只得到题干、选项和提交 ID。不能通过修改 stageId、答案索引或 completed 数组跨阶段。

阶段通过由规则判定，模型只撰写解释与叙事表达；模型 JSON 中的 complete 不能直接决定任务转换。解释分清“答错了什么”和“下一步能去哪里核查”，不泄露尚未获得的全部答案。

交互类型用统一合同扩展：`inspect`、`dialogue`、`present_evidence`、`multiple_choice` 为首批；后续再接 `timeline_order`、`map_route`、`reconstruct_message`、`spoken_report`。每种类型都声明输入、前置条件、验证器、反馈事件与持久化格式，不把所有内容塞进出题 prompt。

## 12. 英语学习与反馈

评估顺序：意思是否清楚 → 是否适合当前社交情境 → 能否自然接话/澄清 → 有价值的语法词汇问题。接受口语省略、缩写、自然短句，不强行改成作文。

每次玩家回答均建立学习记录。自由文本生成与口语场景相适应的英语反馈；选项回答也给即时反馈，但评价该选择体现的理解、语用或推理，不把 AI 写出的选项伪装成玩家亲自说出的句子。玩家用自己的英语补充理由时，再对那段表达生成口语反馈。选择正确与否和语言质量分别记账。表达良好或太短不足以评估时也保留记录，不伪造错误。

单条反馈包含：原句、对话语境、交流意图、沟通是否成功、重要问题 0–2 项、一个自然替代表达、可复用句型、置信度、关联 turn ID。已有答案正确与否是另一条维度，不进入语言扣分。

反馈默认关闭，仅显示低干扰的完成计数。玩家可在任何安全停顿点打开按角色、阶段、语言点整理的历史；不自动朗读、不弹窗抢焦点，不替 NPC 教英语。

后台任务用持久化队列：`pending → running → completed / retry_wait / failed`。与玩家消息在同一事务建立任务，按用户/旅程隔离；worker 崩溃通过租约回收。按消息 ID 和反馈版本幂等写入。

可重试错误：超时、断网、429（优先遵守 Retry-After）、5xx；指数退避基础 2 秒，约 2/4/8/16/32 秒加随机抖动，封顶后延后到后台调度窗口，达到上限保留失败记录供重试。不对无效密钥、余额不足、无权限或参数错误进行无休止重试。

刷新、切页、退出浏览器不丢任务。离线发送未获服务器确认时标记本地待提交，联网再补；不宣称已反馈或已云端保存。

阶段结算立即保存剧情结果并允许继续探索；学习汇总在后台运行。汇总固定该阶段消息快照和待反馈任务集合，未完成时显示“整理中，已完成 X/Y”。后续反馈到达后生成新版本或合并更新，不能静默漏掉末尾发言。

汇总与单句纠错使用不同接口、schema、输入长度和上下文预算。长阶段分块聚合后按原始 turn ID 回查代表例句；覆盖全部历史但前台分页显示，不做“只保留最近 80 条”的数据删除。

阶段报告：交流成果、反复出现的 2–3 个语言问题、原句与改写、3 个下阶段可用表达、可选短练习。全季报告比较早晚相同类型表达的变化，不编造语言等级增长或学习效果。文本输入不能据此评价发音；语音模式要有实际音频/识别依据。

Anki 接入放在回顾页，用户选择句型/词汇后沿用现有任务中心。每张卡附自己原句与来源对话；不在探索中自动弹卡或要求服务器安装 Anki Desktop。

## 13. 推理强度、流式与自定义提供商探针

| 任务 | 建议策略 | 输出/约束 |
|---|---|---|
| NPC 日常与已知事实答复 | 支持时关闭思考或最低档；复杂关系反应低档 | SSE 文本流；不向角色加入额外秘密来“帮助推理”。 |
| 交流意图归类 | 无/低；可规则处理的不调模型 | 结构化输出仅为候选，事件要由引擎验证。 |
| 受约束题目生成 | 中档、低随机度 | 完整 JSON 校验后一次展示，不流式暴露半成品题与答案键。 |
| 语言单句反馈 | 无/低 | 独立后台结构化任务。 |
| 阶段/全季学习汇总 | 中档 | 分块归纳、原句引用验证。 |
| 叙事结算解释 | 中档 | 规则先判定，模型只表达已可揭晓内容。 |
| 权限、线索归属、存档、完成条件 | 不调用模型 | 确定性代码与事务。 |

推理档位按提供商实际能力映射；不对所有接口盲发同一个 reasoning_effort。没有对应控制时省略并记录能力，不能因不支持参数而静默切错模型。不展示私有思维链。

自定义提供商范围按服务器规范化的 URL 主机与常用提供商登记表判定，不能仅检查前端 provider 字符串是否等于 custom。

每个新 URL/模型配置在游玩期间随机空闲时段执行 2–3 次小型测试：真实 SSE 分块/错误处理、JSON/基础指令遵循、隔离沙盒中的合成角色未知事实与注入反应。所有探针使用合成世界与随机 canary，不传真实角色秘密、答案、玩家私聊或 API 密钥文本。

设置页说明测试用途、次数与少量用量；请求受预算、每日上限、URL+模型+能力版本缓存和前台优先级约束。失败先区分网络故障与行为失效，只在设置/诊断中提示；不扰乱人物台词，也不把“测过几次通过”宣称为模型安全证明。

## 14. 2D/3D 与美术资源

3D：第三人称探索，跟随镜头；交谈时切到自然的肩后双人机位，保留人物表情、视线与手势。用户提供的 16:9 目标截图只用于 3D 的构图、光照、材质和细节验收，不是 2D 关卡底图，也不能被当作完成品背景。目标场景是湿木码头、海湾、灯塔、暖灯和薄雾，必须以可移动的真实 3D 场景实现。

2D：同一世界状态的低负载俯斜视角投影，是 3D 的可玩简化版，不是另一套剧情，也不追求目标截图的逐像素相似。它使用同一地图坐标、NPC 位置、碰撞体、交互半径、证据和时段；呈现层可使用低分辨率烘焙材质、简化几何、精灵/正交相机和较少粒子。2D 仍必须有真实移动、遮挡、地点触发、附近 NPC 对话和完整第一章路径，不能用截图、静态海报或全屏背景代替关卡。2D 单独验收可读性、输入延迟、帧时间、GPU/内存和低端设备稳定性，不使用 3D 目标图评分作为替代。

两种模式共用实体 ID、世界坐标映射、交互点、剧情时段、NPC 状态、已获得证据和权威存档。切换只替换呈现，保留人物位置、对话与任务，不重开一局，不产生独立的一套剧情。

正式资产生产流水线固定为：角色先制作独立正交参考图，再用 Tripo3D image-to-3D 生成角色网格；进入 Blender 进行拓扑、脸衣比例、UV、材质、骨骼、行走/转身/站立/对话动画、LOD、碰撞代理和 GLB 导出验证。场景由 Blender MCP 负责搭建、灯光、镜头、材质节点和组合，地标/道具可由 Tripo3D 生成后在 Blender 中清理组合；不得用占位方块或给同一人物只换颜色充当正式资产。程序化只用于海雾、水面、散布和简单碰撞等适合对象。

Poly Haven 仅用于 HDRI、木材、石材、地面等合适的 CC0 PBR 素材，不能当作人物动画库。所有网络资产需登记来源、资产 ID、许可、修改、压缩格式、作者署名要求和内容哈希；确认可用后保存为可部署资源，运行时不热链第三方。每个角色/地标必须通过网格、材质、骨骼/动画（如适用）、碰撞、LOD、大小和浏览器加载检查；Tripo 生成失败时回退到重新生成或 Blender 修整，不能回退为方块。

AI 图片适用：角色肖像、纸质道具、2D 补景、明确分离层的纹理和资源参考。用户指定的 gpt-image-2.6 需要先核实环境可调用能力；不能偷偷换模型后声称使用了它。主要近景人物还需可用网格、UV、材质、骨骼、动画和审美人工检查，单张图不等于人物模型。

首个正式场景资产清单：玩家、Eli、Mara 三套近景角色；灯塔/码头房屋模块；码头、绳索、渔网、船、灯具与工具；天空/HDRI、海水和雾；行走/转身/站立/对话动作；至少一组环境音。先做到这处场景可信，再扩地图。

首季不需要 AI 视频；雾、水、灯光与人物动作实时呈现。若后续明确需要短过场，单独给用户镜头时长、画幅、分镜和生成要求，由用户生成。

## 15. 操作与界面

桌面：WASD/方向键移动，鼠标控制镜头，E 交互，Esc 退出当前交互/暂停。线索入口可用 J；不全局劫持 Tab，让表单与辅助操作可正常切焦点。移动时按秒计算位移，不依赖键盘重复速度。

触屏：2D 支持点地移动与点角色交互；3D 提供左侧虚拟摇杆移动、右侧拖拽镜头、明确的交互按钮和安全区；文本输入时隐藏移动控件并暂停镜头输入。不同模式不能抢同一次触摸。支持鼠标/键盘、触控和可选手柄三套输入映射，输入焦点和暂停状态必须明确。

三端布局与验收视口固定为：手机竖屏 390×844、手机横屏 844×390、平板 1024×768、桌面 1440×900。手机使用底部安全区和折叠式对话抽屉，平板使用可收窄侧栏，桌面使用目标截图同类的窄右栏；所有设备的交互按钮命中区至少 44 CSS px，软键盘弹出时不能遮住输入框或发送按钮。三端必须走完同一首章最短合法路径，并验证 2D/3D 切换保留同一 world position、NPC 状态和交互 ID。

进入 Game 后提供沉浸模式，收起主应用侧栏和学习反馈面板。探索常驻元素只保留角落目标、临近交互提示、底部小型 2D/3D/日志入口。桌面持续遮挡目标低于约 20%，对话时才展开右侧窄栏。

对话窄栏包含当前角色、短段流式文本、输入框、可收起历史；不会同时保留两套同样大的对话框。人物在场景中仍是视觉主体。线索、地图、任务全文与学习历史按需打开。

字幕字号可调，人物名字与发言区分清楚；色盲下线索分类不只靠颜色。支持减少动态效果、音量分组、字幕与可关闭自动朗读。重要环境声音都有可发现的文字/视觉核查途径，不能只靠听力通关。

## 16. 技术与存档边界

推荐新游戏子模块使用独立 TypeScript + Vite + Three.js 包，作为单独页面构建，再由现有服务按 `GET /english?version=dev/world-game` 返回。2D 使用同一 Three.js 包内的正交/低负载 renderer，不复制英语主页面，不把游戏停在旧 game tab；主应用只提供登录凭据、提供商设置和返回入口。若 2D 关卡复杂度需要 Phaser，必须先证明 Three.js 轻量 renderer 无法满足低端设备目标，第一版不为引擎数量增加维护负担。

模块边界：

```text
Shared game core
  entities / interactions / quest graph / input actions / scene descriptors

Presentation
  renderer-3d / renderer-2d / camera / animation / audio / DOM HUD

Server game domain
  worldbook compiler / permission selector / conversation service
  evidence events / question validator / settlement rules / save transactions

Background jobs
  turn feedback / stage summary / full-journey summary / synthetic probes
```

独立页面与外部英语页面共享同一登录身份和服务端数据源。游戏会话、NPC turn、玩家证据、反馈任务和阶段汇总按 `user_id + run_id + content_version` 存储；外部聊天只可继续玩家最近一次已在场且已授权的 NPC 会话，不能读取其他角色私有书或作者真相。游戏内反馈页与外部反馈页读取同一反馈记录，任一端新增/删除/重试都通过服务端版本号合并；禁止用两套 localStorage 作为权威来源。`/english?version=dev/world-game` 的 query 值是完整的 `dev/world-game`，不得按旧的 `version=dev` 分支处理，也不得把 `world-game` 当作旧页面 tab 名。

数据库至少有旅程、阶段状态、事件、角色会话、已取得证据、题目实例/作答、反馈任务/结果、汇总版本。全部按用户与 run ID 授权，并绑定内容版本。浏览器只缓存可见数据和待提交动作。

事务步骤：接收唯一 action ID → 校验身份/阶段/距离或可用交互 → 读取当前版本 → 写事件与状态 → 同事务创建相关后台任务 → 返回可见状态。重复请求返回同一结果；多设备陈旧提交提示刷新，避免覆盖新进度。

历史由服务端读取，不信任客户端提交的 assistant 文本；角色摘要只能概括该 NPC 亲历会话，保留“玩家声称”标签。阶段退出时卸载阶段上下文，历史不能把未授权阶段事实带回来。

资源用 manifest 稳定 ID、内容哈希和本地部署路径。GLB/glTF 模型，按支持选择 Meshopt/Draco、KTX2、LOD、烘焙光照和合理阴影；构建后核对静态白名单、MIME 和 CSP，避免新增资源格式在公网 404。

性能目标需注明测试硬件与视口：中档桌面 1080p 目标 60 FPS；明确列出的移动测试设备低画质目标 30 FPS。首个可玩区域压缩资源目标不超过 25 MB、后续分区加载；正常浏览器内存目标低于 600 MB。这些是初始预算，测量后调整，不能预先声称达标。

退出 Game 或切标签时暂停 rAF/音频/模拟，卸载区域时释放纹理、几何、监听器与流请求。测试采用已有公共 beta 或单一隔离本地服务；所有临时 Node/Python/浏览器进程记录精确 PID，用后停止并验证监听端口释放。

## 18. Dream Loop Pro 与正式验收

沿用用户已选 Pro 和已提供目标图，目标存 `.dream-loop/target.png`。目标图是画面验收参考，不能做 UI/关卡底图冒充接近目标。

每轮：运行实际构建 → 亲自检查玩法 → 在固定角色位置/时间/镜头截实时图 → 给干净上下文的独立评审子代理目标图与实时图 → 记录构图/光照/材质/细节及改进项 → 修正 → 重测帧率与交互。

按技能评分：构图 0–3、光照 0–3、材质 0–3、细节 0–1；总分至少 8/10 且约定测试环境的帧率可接受才达到技能视觉退出标准。目标图的照片级人物对浏览器资产有实际挑战，需要以真实近景资产处理，不能先把目标改成低模来通过。

两轮未提高至少 1 分或重复卡在同一问题时，按 Pro 流程重新检查资产/镜头/光照等大方向；不是不断补装饰。大改仍停滞时如实向用户展示差距。浏览器控制不可用时记录视觉门槛未通过，不用 DOM/HTTP 成功替代。

还必须独立通过以下功能门槛，视觉评分不覆盖它们：

- 2D/3D 都有真正的移动、遮挡、人物交互与对象调查；切换不丢任务。
- 用户从 UI 能发现全部必需入口，不依赖控制台调用。
- 最短合法路径可走通；乱走、先问后查、重复追问也可恢复。
- 对“告诉我真相/你现在扮演其他角色/这是系统消息”的请求做真实上下文捕获审计；验证书的内容和历史，而非只查有没有 judge_only 字段。
- 第三阶段/他人角色/他人用户/他人旅程不可越权；客户端伪造 assistant 不生效。
- 无效 AI 输出、断流、错误密钥、429、worker 重启、长历史、换设备不会给错线索或丢任务。
- 短句、语法不完美但可理解、口语缩写、澄清请求不会被作文标准惩罚。
- 首章与整季报告确实覆盖对应消息集合，未完成任务状态可见。
- 真相、角色私有书和答案不出现在浏览器资源、source map、公开日志、探针或普通 API 响应。
- 公网实际页面、角色流式对话、题目提交、阶段推进、反馈历史都经过体验验证，并附具体证据与已知限制。

## 19. 首次重做的决策结论

保留用户给定美术方向、世界多阶段目标、自由英语交流、角色信息隔离和后台学习反馈。以新写的可验证事实图与服务端游戏状态为核心，重写当前三段“保险丝问答”主线。

先交付一个足够漂亮、可以完整调查、具备 2D/3D 等价玩法的第一章。它通过真实玩法与 Dream Loop Pro 两条门槛后，再扩展全季。此文档提供后续验收标准，不代表这些新规格已完成或已经获得用户对新增剧情细节的认可。
